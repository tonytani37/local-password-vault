# ローカル・パスワードマネージャー 仕様書

版数: 1.0 ／ 作成日: 2026年11月6日

## 1. 概要

本書は、ローカルPC上で動作するパスワード管理アプリケーション（以下「本システム」）の仕様を定めるものである。インターネットのWebサイトに限らず、ライセンスキー・機器のパスワードなど、URL未登録の情報も管理できる。

- 保存データ（タイトル・URL・ユーザー名・パスワード）はすべて暗号化してSQLiteに保存する。
- 暗号鍵はマスターパスワードから都度計算し、どこにも保存しない。
- サーバーは自分のPC（127.0.0.1）からの接続のみを受け付ける。(インターネット接続なし)

## 2. 動作環境と構成

### 2.1 動作環境

| 項目 | 内容 |
|---|---|
| 実行環境 | Node.js 22.13 以上（`node:sqlite` を使用） |
| 依存パッケージ | hono、@hono/node-server、csv-parser |
| データベース | SQLite（Node.js組み込みの `node:sqlite`） |
| 待受 | 127.0.0.1:3000（ローカルのみ） |
| クライアント | Webブラウザ（Chrome等） |

### 2.2 フォルダ構成

```
root\
  start.bat          起動用バッチ(Windows版　macOS,Linux版はstart.sh)
  node.exe           Node.js 本体
  server.mjs         サーバー本体
  package.json
  public\index.html  画面
  vault.db           SQLiteデータベース（初回起動時に自動作成）
  backups\           バックアップ（システム終了時に自動作成。最大履歴10）
```

- フォルダ構成に含まれるファイルを利用したいPCにそのままコピーし、start.bat(macOS,Linuxの場合は、start.sh)からシステムを起動する。

- 上記ファイル群以外、事前にPCに関連ソフト等のインストールは不要です。

- vault.db と backups は、server.js の置かれたフォルダを基準に作成される（起動時のカレントディレクトリには依存しない）。

## 3. 機能仕様

| 機能 | 内容 |
|---|---|
| 初期設定 | マスターパスワード（12文字以上、1024文字以下）を設定する。設定は一度のみで、設定済みの場合は再実行を拒否する（409）。 |
| ログイン | マスターパスワードで認証し、セッショントークンを発行する。 |
| 自動ロック | 無操作10分でセッションが失効する。操作のたびに期限は延長される。 |
| 登録済み一覧 | 全件を表示する。タイトル・URL・ユーザー名で絞り込み検索ができる。件数を表示する。 |
| 新規登録 | タイトル・パスワードは必須。URL・ユーザー名は任意（URL未登録も可であり、ローカルのソフト等へのログイン情報の保存も可）。 |
| 削除 | 確認ダイアログの後に1件ずつ削除する。 |
| パスワード表示 | 通常はマスク表示。「表示」で表示、「コピー」でクリップボードへコピーし、30秒後に空文字で上書きする。 |
| CSVインポート | Chromeの書き出しCSV（name, url, username, password 列）を取り込む。パスワードが空の行はスキップし、取り込み件数とスキップ件数を表示する。取り込み分は一覧で黄色く強調する。 |
| ログアウト | サーバー上のセッション鍵を破棄し、画面上のデータを消去する。 |
| バックアップ | 起動時とシャットダウン時に vault.db のコピーを作成する。最大10個を保持し、超えた分は古いものから削除する。 |

画面は「登録済み一覧」タブと「新規登録」タブ（新規登録・CSVインポート）に分かれる。

## 4. API仕様

認証が「要」のAPIは、`Authorization: Bearer <token>` ヘッダーが必要。無効・期限切れの場合は 401（code: SESSION_EXPIRED）を返す。POST・DELETE には Origin ヘッダーの検証がある。

| メソッド | パス | 認証 | 概要 |
|---|---|---|---|
| GET | / | 不要 | 画面（index.html）を返す |
| GET | /api/status | 不要 | 初期設定済みかを返す |
| POST | /api/setup | 不要 | 初期設定（設定済みなら 409） |
| POST | /api/login | 不要 | ログイン。トークンと有効期間を返す |
| POST | /api/logout | 要 | セッション破棄 |
| GET | /api/credentials | 要 | 全件を復号して返す |
| POST | /api/credentials | 要 | 1件追加 |
| DELETE | /api/credentials/:id | 要 | 1件削除 |
| POST | /api/import-csv | 要 | CSVインポート（multipart、file フィールド） |

主なエラー: 400（入力不正）、401（認証失敗・セッション無効）、403（Host/Origin不正）、404（対象なし）、409（設定済み）、413（CSVが5MB超）、429（ログイン試行過多）、500（内部エラー。詳細は返さない）。

## 5. データ仕様（DBスキーマ）

### 5.1 system_config（管理情報）

| key | 内容 |
|---|---|
| password_salt | 鍵導出用のソルト（32バイト乱数、16進） |
| kdf_iterations | 鍵導出の反復回数（初期設定時の値を保存） |
| password_hash | マスターパスワード照合用の値 |

### 5.2 credentials（資格情報）

| 列 | 内容 |
|---|---|
| id | 自動採番の主キー |
| iv | 初期化ベクトル（12バイト乱数、Base64） |
| auth_tag | GCM認証タグ（Base64） |
| data | title・url・username・password をまとめたJSONの暗号文（Base64） |
| created_at | 登録日時 |

タイトル・URL・ユーザー名もパスワードと同様に暗号化される。平文で保存される項目はない。

## 6. 暗号仕様

1. マスターパスワードとソルトから、PBKDF2-HMAC-SHA512（210,000回）で64バイトを導出する。
2. 前半32バイトのSHA-256を、照合用の `password_hash` とする。
3. 後半32バイトを、データ暗号化鍵とする（保存しない）。
4. データは AES-256-GCM で暗号化する。レコードごとに新しい12バイトのIVを使い、認証タグで改ざんを検出する。

照合用の値と暗号化鍵は、導出結果の別の部分から作るため、`password_hash` から暗号化鍵を計算することはできない。

## 7. セキュリティ仕様（不正アクセスへの耐性）

### 7.1 脅威と対策

| 脅威 | 対策 | 残存リスク |
|---|---|---|
| vault.db・バックアップの盗難 | 全項目をAES-256-GCMで暗号化。鍵は保存せず、マスターパスワードからのみ導出。 | 弱いマスターパスワードは、オフラインの総当たりで破られうる。 |
| 管理情報テーブルの削除・書き換え | 別のパスワードで再設定しても、ソルトが変わり鍵が一致しないため復号できない（「復号に失敗しました」と表示）。 | 管理情報が消えると初期設定をやり直せる。正規の利用者も復号できなくなる。 |
| 初期設定の再実行による乗っ取り | 設定済みなら /api/setup は 409 を返す。 | 管理情報が削除された場合は上記のとおり。 |
| LAN・外部からの接続 | 127.0.0.1 のみで待ち受ける。 | 同じPC上の他のプロセスは接続可能（ただしログインにはマスターパスワードが必要）。 |
| DNSリバインディング | Hostヘッダーを 127.0.0.1:3000 / localhost:3000 のみ許可。 | なし |
| 他サイトからの不正リクエスト（CSRF） | POST・DELETE は許可した Origin のみ受け付ける。トークンは Cookie ではなくヘッダーで送る。 | なし |
| ログイン総当たり | 5回失敗でロックし、1秒から倍々に延長（最大5分）。成功でリセット。 | 試行回数は全体で数える。攻撃者の失敗で、正規利用者も一時的にログインできなくなる。 |
| タイミング攻撃 | 照合値の比較に timingSafeEqual を使用。 | なし |
| セッションの盗用 | 256ビット乱数のトークン。利用PCのメモリ内のみに保持し、無操作10分で失効。ログアウト・失効時に鍵を0で上書き。ブラウザ側もメモリ上にのみ保持（localStorage不使用）。 | 同一ブラウザ上で実行されるスクリプトには対抗できない。 |
| XSS | 一覧は textContent で描画。リンクは http/https のみ。CSP、X-Frame-Options: DENY、nosniff、Referrer-Policy: no-referrer を付与。 | スクリプト実行の都合で CSP に inline script を許可している。 |
| 不正な入力 | 型・長さを検証（各項目4096文字、マスターパスワード1024文字、CSV 5MB）。 | なし |
| CSVの平文漏えい | CSVはメモリ上でのみ処理し、ディスクへ書かない。 | 元のCSVファイルは平文であるため、利用後に利用者が完全に削除する必要がある。 |
| 削除データの残留 | SQLite の secure_delete を有効化。 | OSやストレージの仕様による残留は防げない。 |
| 内部情報の漏えい | 想定外のエラーは汎用メッセージのみ返す。 | なし |
| キャッシュからの漏えい | 全レスポンスに Cache-Control: no-store を付与。 | なし |

### 7.2 防げないもの（前提）

- マルウェア感染、キーロガー、メモリの読み取りなど、PC自体が侵害された状態。
- ブラウザの拡張機能による画面内容の読み取り。
- マスターパスワード自体の漏えい・使い回し。
- クリップボード履歴の機能（Windows のクリップボード履歴など）に、コピーしたパスワードが残ること。

## 8. バックアップと復旧

- 起動時とシャットダウン時（Ctrl+C）に、`backups\vault_<日時>.db` を作成する。SQLiteの `VACUUM INTO` で整合性のあるコピーを作る。
- 最大10個を保持し、超えた分は古いものから削除する。
- バックアップ内のデータも暗号化済みであり、ソルトを含むため、そのまま保管できる。
- コンソールを直接閉じた場合は、終了時バックアップが作成されないことがある。

復旧手順:

1. サーバーを停止する。
2. 現在の vault.db を別名で退避する。
3. `backups\` の対象ファイルをコピーし、`vault.db` に名前を変更して置く。
4. サーバーを起動し、元のマスターパスワードでログインする。

## 9. 運用上の注意

- マスターパスワードを忘れると、データは復元できない（バックアップからも不可）。
- バックアップは同じPC内にあるため、最新のものを別のドライブやUSBメモリへ定期的にコピーする。
- CSVは平文でエクスポートされるため、インポート後は元のCSVを完全に削除する。
- PC全体の保護として、Windowsのサインインパスワードと BitLocker の利用を推奨する。
- バッチは前面で実行されるため、終了は Ctrl+C で行う。

## 10. 既知の制限と今後の改善候補

| 項目 | 内容 |
|---|---|
| 編集機能 | 未実装（追加と削除のみ）。 |
| マスターパスワード変更 | 未実装（不正改ざん対策の検討が必要）。 |
| データ存在時の再初期設定 | 保存データがあるのに管理情報がない場合も、現状は初期設定を受け付ける。拒否して復旧を促す対策を推奨する（未実装）。 |
| 行の差し替え・巻き戻し | GCMのAAD（追加認証データ）を使っておらず、行の入れ替えや古いバックアップへの巻き戻しは検出できない。読み取りはできない。 |
| ログインのロック | 全体で数えるため、IPごと等の区別はない。 |
| node:sqlite | Node.js側で実験的機能の扱いのため、将来のバージョンで仕様が変わる可能性がある。 |
