# ローカル・パスワードマネージャー

版数: 1.1 ／ 改訂日: 2026年11月24日（初版: 2026年11月6日）

## 1. 概要

本書は、ローカルPC上で動作するパスワード管理アプリケーション（以下「本システム」）の仕様を定めるものである。インターネットのWebサイトに限らず、ライセンスキー・機器のパスワードなど、URL未登録の情報も管理できる。

- 保存データ（タイトル・URL・ユーザー名・パスワード）はすべて暗号化してSQLiteに保存する。
- 暗号鍵はマスターパスワードから都度計算し、どこにも保存しない。
- サーバーは自分のPC（127.0.0.1）からの接続のみを受け付ける。
- **【1.1追加】Cloudflare R2 同期対応**：環境変数を設定することで、暗号化済みの `vault.db` ファイルを Cloudflare R2 と自動同期し、複数の端末間でデータを共有できる（未設定時は従来の完全ローカル単体モードで動作する）。

## 2. 動作環境と構成

### 2.1 動作環境

|---|---|
| 実行環境 | Node.js 22.13 以上（`node:sqlite` を使用） |

| クラウド同期（任意） | Cloudflare R2（S3互換API / AWS Signature V4 を Node.js 標準機能のみで実装） |
| 待受 | 127.0.0.1:3000（ローカルのみ）[cite: 10] |
| クライアント | Webブラウザ（Chrome等）[cite: 10] |

- フォルダ構成に含まれるファイルを利用したいPCにそのままコピーし、`start.bat`（macOS, Linuxの場合は `start.sh`）からシステムを起動する[cite: 10]。

- `vault.db` と `backups` は、環境変数による明示指定がない限り `server.mjs` の置かれたフォルダを基準に作成される（起動時のカレントディレクトリには依存しない）[cite: 10]。

### 2.3 環境変数（Cloudflare R2 同期・パス設定）

すべて任意設定。R2関連の4項目がすべて設定されている場合のみ「Cloudflare R2 同期モード」で起動し、未設定の場合は従来の「ローカル単体モード」で起動する。

| 変数名 | 必須/任意 | 内容 |
|---|---|---|
| `R2_ACCOUNT_ID` | 任意（R2利用時は必須） | Cloudflare のアカウントID |
| `R2_BUCKET` | 任意（R2利用時は必須） | 保存先の Cloudflare R2 バケット名 |
| `R2_ACCESS_KEY_ID` | 任意（R2利用時は必須） | R2 API トークンのアクセスキーID |
| `R2_SECRET_ACCESS_KEY` | 任意（R2利用時は必須） | R2 API トークンのシークレットアクセスキー |
| `R2_OBJECT_KEY` | 任意 | R2上の保存ファイル名（デフォルト: `vault.db`） |
| `VAULT_DB_PATH` | 任意 | ローカルの `vault.db` 保存先パス（デフォルト: `server.mjs` と同階層） |
| `VAULT_BACKUP_DIR` | 任意 | ローカルのバックアップ保存先フォルダ（デフォルト: `server.mjs` 配下の `backups`） |

## 3. 機能仕様

| 機能 | 内容 |
|---|---|
| 初期設定 | マスターパスワード（12文字以上、1024文字以下）を設定する。設定は一度のみで、設定済みの場合は再実行を拒否する（409）。R2有効時は即座にR2へアップロードする[cite: 10]。 |
| ログイン | マスターパスワードで認証し、セッショントークンを発行する[cite: 10]。 |
| 自動ロック | 無操作10分でセッションが失効する。操作のたびに期限は延長される[cite: 10]。 |
| 登録済み一覧 | 全件を表示する。タイトル・URL・ユーザー名で絞り込み検索ができる。件数を表示する[cite: 10]。 |
| 新規登録 | タイトル・パスワードは必須。URL・ユーザー名は任意（URL未登録も可であり、ローカルのソフト等へのログイン情報の保存も可）。R2有効時は登録後に即座にR2へ同期する[cite: 10]。 |
| 削除 | 確認ダイアログの後に1件ずつ削除する。R2有効時は削除後に即座にR2へ同期する[cite: 10]。 |
| パスワード表示 | 通常はマスク表示。「表示」で表示、「コピー」でクリップボードへコピーし、30秒後に空文字で上書きする[cite: 10]。 |
| CSVインポート | Chromeの書き出しCSV（name, url, username, password 列）を取り込む。パスワードが空の行はスキップし、取り込み件数とスキップ件数を表示する。取り込み分は一覧で黄色く強調する。R2有効時は取込後に即座にR2へ同期する[cite: 10]。 |
| ログアウト | サーバー上のセッション鍵を破棄し、画面上のデータを消去する[cite: 10]。 |
| バックアップ | シャットダウン時に `vault.db` のコピーを作成する。最大10個を保持し、超えた分は古いものから削除する[cite: 10]。 |
| **【1.1追加】R2同期・排他制御** | 起動時にR2から最新の `vault.db` と `ETag` を取得してローカルを上書きする。変更時は `If-Match` ヘッダ付きでアップロードし（最大3回リトライ）、他端末による先行更新（412）を検知した場合は上書きをブロックして閲覧専用モードへ移行する。 |
| **【1.1追加】オフライン閲覧専用モード** | 起動時にネットワーク不調等でR2へ接続できない場合、ローカルに残っている直前の `vault.db` キャッシュを開いて「閲覧専用モード」で起動する。既存データの検索・表示・コピーは利用可能で、新規登録・削除・CSVインポートはロックされる。 |

画面は「登録済み一覧」タブと「新規登録」タブ（新規登録・CSVインポート）に分かれる（オフライン閲覧専用モード時は「新規登録」タブおよび「削除」ボタンが非表示となり、画面上部に警告バナーを表示する）[cite: 10]。

## 4. API仕様

認証が「要」のAPIは、`Authorization: Bearer <token>` ヘッダーが必要[cite: 10]。無効・期限切れの場合は 401（code: SESSION_EXPIRED）を返す[cite: 10]。POST・DELETE には Origin ヘッダーの検証がある[cite: 10]。また、閲覧専用モード（`isReadOnly === true`）の場合、変更系API（`/api/setup`, `/api/credentials` POST/DELETE, `/api/import-csv`）は 503 を返す。

| メソッド | パス | 認証 | 概要 |
|---|---|---|---|
| GET | / | 不要 | 画面（index.html）を返す[cite: 10] |
| GET | /api/status | 不要 | 初期設定済みか（`isInitialized`）および閲覧専用モードか（`readOnly`）を返す[cite: 10] |
| POST | /api/setup | 不要 | 初期設定（設定済みなら 409、閲覧専用時は 503）[cite: 10] |
| POST | /api/login | 不要 | ログイン。トークンと有効期間を返す[cite: 10] |
| POST | /api/logout | 要 | セッション破棄[cite: 10] |
| GET | /api/credentials | 要 | 全件を復号して返す[cite: 10] |
| POST | /api/credentials | 要 | 1件追加（閲覧専用時は 503）[cite: 10] |
| DELETE | /api/credentials/:id | 要 | 1件削除（閲覧専用時は 503）[cite: 10] |
| POST | /api/import-csv | 要 | CSVインポート（multipart、file フィールド。閲覧専用時は 503）[cite: 10] |

主なエラー: 400（入力不正）、401（認証失敗・セッション無効）、403（Host/Origin不正）、404（対象なし）、409（設定済み）、413（CSVが5MB超）、429（ログイン試行過多）、500（内部エラー・ETag不一致エラー）、503（オフライン閲覧専用モードによる書き込み制限）[cite: 10]。

## 5. データ仕様（DBスキーマ）

### 5.1 system_config（管理情報）[cite: 10]

| key | 内容 |
|---|---|
| password_salt | 鍵導出用のソルト（32バイト乱数、16進）[cite: 10] |
| kdf_iterations | 鍵導出の反復回数（初期設定時の値を保存）[cite: 10] |
| password_hash | マスターパスワード照合用の値[cite: 10] |

### 5.2 credentials（資格情報）[cite: 10]

| 列 | 内容 |
|---|---|
| id | 自動採番の主キー[cite: 10] |
| iv | 初期化ベクトル（12バイト乱数、Base64）[cite: 10] |
| auth_tag | GCM認証タグ（Base64）[cite: 10] |
| data | title・url・username・password をまとめたJSONの暗号文（Base64）[cite: 10] |
| created_at | 登録日時[cite: 10] |

タイトル・URL・ユーザー名もパスワードと同様に暗号化される[cite: 10]。平文で保存される項目はない[cite: 10]。R2上にアップロードされる `vault.db` もこの暗号化済みSQLiteファイルそのものである。

## 6. 暗号仕様

1. マスターパスワードとソルトから、PBKDF2-HMAC-SHA512（210,000回）で64バイトを導出する[cite: 10]。
2. 前半32バイトのSHA-256を、照合用の `password_hash` とする[cite: 10]。
3. 後半32バイトを、データ暗号化鍵とする（保存しない）[cite: 10]。
4. データは AES-256-GCM で暗号化する[cite: 10]。レコードごとに新しい12バイトのIVを使い、認証タグで改ざんを検出する[cite: 10]。

照合用の値と暗号化鍵は、導出結果の別の部分から作るため、`password_hash` から暗号化鍵を計算することはできない[cite: 10]。また、暗号化・復号はすべてローカルPC上の Node.js プロセス内でのみ完結し、Cloudflare R2 には暗号化済みのDBバイナリのみが送信される（ゼロ知識設計）。

## 7. セキュリティ仕様（不正アクセスへの耐性）

### 7.1 脅威と対策

| 脅威 | 対策 | 残存リスク |
|---|---|---|
| vault.db・バックアップ・R2上のデータの盗難 | 全項目をAES-256-GCMで暗号化。鍵は保存せず、マスターパスワードからのみ導出。R2へも暗号化済みファイルのみ送信。 | 弱いマスターパスワードは、オフラインの総当たりで破られうる[cite: 10]。 |
| 管理情報テーブルの削除・書き換え | 別のパスワードで再設定しても、ソルトが変わり鍵が一致しないため復号できない（「復号に失敗しました」と表示）[cite: 10]。 | 管理情報が消えると初期設定をやり直せる。正規の利用者も復号できなくなる[cite: 10]。 |
| 初期設定の再実行による乗っ取り | 設定済みなら /api/setup は 409 を返す[cite: 10]。 | 管理情報が削除された場合は上記のとおり[cite: 10]。 |
| 複数端末からの同時書き込み・先祖返り | 起動時にR2の ETag を取得し、更新時に `If-Match` ヘッダで検証。不一致（412）時は上書きを拒否し閲覧専用モードへ移行。 | 同時並列での編集（マージ）には非対応。 |
| LAN・外部からの接続 | 127.0.0.1 のみで待ち受ける[cite: 10]。 | 同じPC上の他のプロセスは接続可能（ただしログインにはマスターパスワードが必要）[cite: 10]。 |
| DNSリバインディング | Hostヘッダーを 127.0.0.1:3000 / localhost:3000 のみ許可[cite: 10]。 | なし[cite: 10] |
| 他サイトからの不正リクエスト（CSRF） | POST・DELETE は許可した Origin のみ受け付ける。トークンは Cookie ではなくヘッダーで送る[cite: 10]。 | なし[cite: 10] |
| ログイン総当たり | 5回失敗でロックし、1秒から倍々に延長（最大5分）。成功でリセット[cite: 10]。 | 試行回数は全体で数える。攻撃者の失敗で、正規利用者も一時的にログインできなくなる[cite: 10]。 |
| タイミング攻撃 | 照合値の比較に timingSafeEqual を使用[cite: 10]。 | なし[cite: 10] |
| セッションの盗用 | 256ビット乱数のトークン。利用PCのメモリ内のみに保持し、無操作10分で失効。ログアウト・失効時に鍵を0で上書き。ブラウザ側もメモリ上にのみ保持（localStorage不使用）[cite: 10]。 | 同一ブラウザ上で実行されるスクリプトには対抗できない[cite: 10]。 |
| XSS | 一覧は textContent で描画。リンクは http/https のみ。CSP、X-Frame-Options: DENY、nosniff、Referrer-Policy: no-referrer を付与[cite: 10]。 | スクリプト実行の都合で CSP に inline script を許可している[cite: 10]。 |
| 不正な入力 | 型・長さを検証（各項目4096文字、マスターパスワード1024文字、CSV 5MB）[cite: 10]。 | なし[cite: 10] |
| CSVの平文漏えい | CSVはメモリ上でのみ処理し、ディスクへ書かない[cite: 10]。 | 元のCSVファイルは平文であるため、利用後に利用者が完全に削除する必要がある[cite: 10]。 |
| 削除データの残留 | SQLite の secure_delete を有効化[cite: 10]。 | OSやストレージの仕様による残留は防げない[cite: 10]。 |
| 内部情報の漏えい | 想定外のエラーは汎用メッセージのみ返す[cite: 10]。 | なし[cite: 10] |
| キャッシュからの漏えい | 全レスポンスに Cache-Control: no-store を付与[cite: 10]。 | なし[cite: 10] |

### 7.2 防げないもの（前提）

- マルウェア感染、キーロガー、メモリの読み取りなど、PC自体が侵害された状態[cite: 10]。
- ブラウザの拡張機能による画面内容の読み取り[cite: 10]。
- マスターパスワード自体の漏えい・使い回し[cite: 10]。
- クリップボード履歴の機能（Windows のクリップボード履歴など）に、コピーしたパスワードが残ること[cite: 10]。

## 8. バックアップと復旧

- シャットダウン時（Ctrl+C）に、`backups\vault_<日時>.db` を作成する。SQLiteの `VACUUM INTO` で整合性のあるコピーを作る[cite: 10]。
- 最大10個を保持し、超えた分は古いものから削除する[cite: 10]。
- バックアップ内のデータも暗号化済みであり、ソルトを含むため、そのまま保管できる[cite: 10]。
- コンソールを直接閉じた場合は、終了時バックアップが作成されないことがある[cite: 10]。

復旧手順（R2有効時はリモート側にも反映するため、サーバーを起動し直す前に環境変数を外すか R2 バケット側へ手動アップロードする）:

1. サーバーを停止する[cite: 10]。
2. 現在の `vault.db` を別名で退避する[cite: 10]。
3. `backups\` の対象ファイルをコピーし、`vault.db` に名前を変更して置く[cite: 10]。
4. （R2同期利用時）退避復旧した `vault.db` を Cloudflare R2 バケットへ手動アップロードして上書きする。
5. サーバーを起動し、元のマスターパスワードでログインする[cite: 10]。

## 9. 運用上の注意

- マスターパスワードを忘れると、データは復元できない（バックアップやR2からも不可）[cite: 10]。
- R2同期を利用する場合、複数端末で同時に起動したまま別々に編集しないこと（`ETag` 検証により先祖返り上書きはブロックされるが、片方の再起動が必要になる）。
- CSVは平文でエクスポートされるため、インポート後は元のCSVを完全に削除する[cite: 10]。
- PC全体の保護として、Windowsのサインインパスワードと BitLocker の利用を推奨する[cite: 10]。
- バッチは前面で実行されるため、終了は Ctrl+C で行う[cite: 10]。

## 10. 既知の制限と今後の改善候補

| 項目 | 内容 |
|---|---|
| 編集機能 | 未実装（追加と削除のみ）[cite: 10]。 |
| マスターパスワード変更 | 未実装（不正改ざん対策の検討が必要）[cite: 10]。 |
| データ存在時の再初期設定 | 保存データがあるのに管理情報がない場合も、現状は初期設定を受け付ける。拒否して復旧を促す対策を推奨する（未実装）[cite: 10]。 |
| 行の差し替え・巻き戻し | GCMのAAD（追加認証データ）を使っておらず、行の入れ替えや古いバックアップへの巻き戻しは検出できない。読み取りはできない[cite: 10]。 |
| ログインのロック | 全体で数えるため、IPごと等の区別はない[cite: 10]。 |
| node:sqlite | Node.js側で実験的機能の扱いのため、将来のバージョンで仕様が変わる可能性がある[cite: 10]。 |
| 同時編集マージ | ファイル単位の同期であるため、2端末で同時に異なるレコードを追加した場合の自動マージには非対応（単独利用・順次利用を前提とする）。 |
